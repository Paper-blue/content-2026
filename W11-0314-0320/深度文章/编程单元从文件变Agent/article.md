Karpathy上周发了条推文。就一句话，说vibe coding不够用了。

很多人没当回事。但这个词，是他自己造的。2025年2月，他在推特上说，以后写代码，告诉AI你要什么就行了，AI来写，你看看差不多就完事。于是这个词，那年火遍了技术圈。

然而一年后，他自己把它淘汰了。

新词叫 **agentic engineering**。意思完全不同了。不再是你跟AI聊天。现在他的做法是，开一组Agent，每个负责一块。他给指令，看输出，跑偏了就介入。结果呢，自己动手写代码的时间，从80%压到了20%。他还说，99%的时间，他根本不碰代码。

:::data Karpathy的工作流变化
- **80% → 20%** — 手写代码占比（翻转前 → 翻转后）
- **99%** — 不直接写代码的时间比例（当前）
- **2025年12月** — coding agent"基本能用"的拐点
:::

他记得一个时间点，2025年12月。在那之前，coding agent基本不能用。过了那个月，突然就能用了。不是哪个产品发布造成的，而是模型越过了某条线。它能读懂一个中等规模的代码库了，能在十几个文件之间做连贯修改。因此，它不再只是补全光标前那一行了。

这条线一旦越过去，竞争的逻辑就变了。不再是谁补全更准，而是谁对Agent的编排，设计得更合理。

目前跑在最前面的，有三个产品。不过它们走的路，完全不一样。

![](section)

先说Cursor。它赌的是一件事，大多数程序员，不想改习惯。

所以它把Agent塞进了IDE里，但是整个工作流，基本没动。你还是打开VS Code，还是看文件树，写代码，跑测试。Agent在后台读你整个代码库，需要的时候才介入。从单行补全到跨文件重构，它都能做。但做完了，你能看到它改了什么，不认可的话，随时可以拒绝。

这个赌注，赌对了。Cursor在2026年初，年化营收到了20亿美元，三个月翻了一倍。可见程序员愿意为这种模式付钱，Agent在旁边，但控制权在我这儿。不过透明是有代价的，Agent的边界很窄。它不能自己跑测试，也不能处理CI管道里的错误，方向盘始终在人手里。

再说Claude Code，它解决的是另一个问题。有经验的开发者，怎么把注意力从写代码上挪开。

它不在IDE里运行，而是一个命令行工具。Agent直接在终端里干活，读文件，写文件，跑命令，看输出，然后根据结果决定下一步。一个任务丢下去，Agent可以自己找问题，写修复，跑测试验证，甚至自己提交commit。Karpathy用它的时候，反复提到的不是某个功能，而是怎么给Agent拆任务。因为任务描述一模糊，Agent就会在错误方向上，跑很远才停下来。

最后是Replit。它更激进，直接把"程序员"这个前提去掉了。

它面向的是有想法，但不会写代码的人。你描述你要什么应用，Agent从零生成整个项目。前端后端数据库部署配置，一起出来。不需要本地环境，也不需要懂Git。应用跑起来的时候，体验确实接近魔法。但是一旦出了问题，性能瓶颈，安全漏洞，莫名其妙的bug，你面对的就是一个完全没参与构建的代码库。修复一个你不理解的系统，往往比从头重写更难。

:::struct
三条路径的人机边界:
Cursor ── Agent在IDE内辅助，人类逐行审查
Claude Code ── Agent在终端自主执行，人类审查结果
Replit ── Agent全自动构建，人类只描述需求
:::

所以说，三条路，三种用户。Cursor赌的是程序员不想变，Claude Code赌的是开发者想把注意力挪走，而Replit直接把"会写代码"这个前提去掉了。

这不是同一个问题的三种答案，而是三家公司，对"我们到底在服务谁"，给出了不同的判断。

那Karpathy自己呢，他站在Claude Code这边。他认为，人类编排Agent，比Agent全自动，能走得更远。

他的理由其实很简单。软件工程，不只是写代码。真正难的是判断。比如说，这个API要不要做向后兼容？这个异常该静默处理，还是该报警？这个数据模型，六个月后还扛得住吗？这些问题，Agent现在答不了。它能替你写90%的代码，但是剩下那10%的判断，必须有一个理解业务上下文的人来做。

> "编程的单元正在从'文件'变成'Agent'。但Agent的单元还是'判断'——而判断是人的。"
> — 对Karpathy观点的提炼

![](section)

不过这件事，还有个更深的问题。

如果编程的基本单元，从文件变成了Agent，那"程序员"这个词，就要重新定义了。一个写了十年C++的工程师，给Agent下指令这件事，他不一定比一个从没写过代码的产品经理做得更好。这听起来反直觉，但事实就是这样。

Karpathy在分享Claude Code经验的时候，提到最多的，不是哪个命令，也不是哪个功能。他说的是，任务描述要清楚，要拆得让Agent能独立完成，还要在Agent的输出里，快速判断哪里跑偏了。

这些其实不是编程能力。写代码和给Agent下指令，是两件事。因此这个鸿沟，可能会成为接下来十年，软件行业最大的人才错配。

1908年，福特T型车量产之后，马车夫这个职业并没有消失。它分裂成了两个新职业。一部分人学会了开车，成为了出租车司机。另一部分人学会了修车，成为了汽车技师。但是有一个能力，变得彻底无用了，那就是驾驭马匹。不是因为马变笨了，而是因为车不需要马。

编程正在经历它的T型车时刻。写代码这个能力不会消失，但是它在程序员技能栈中的权重，正在快速下降。与此同时，上升的是一种还没有被正式命名的能力，让Agent理解你的意图，并在你的监督下，把意图变成可运行的软件。Karpathy管它叫agentic engineering。这个词能不能活下来，不重要。重要的是，它指向的那个变化，已经发生了。
