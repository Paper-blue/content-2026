Karpathy把自己80%的代码工作交给了Agent。Cursor、Claude Code、Replit走了三条完全不同的路。

Andrej Karpathy上周发了条推文，内容很短，但放在那儿挺刺眼：他觉得 vibe coding 这个概念已经不够用了。

这话刺眼，是因为这个词是他发明的。2025年2月他在推特上造了这个词，用来描述一种新的编程方式——你用自然语言告诉AI你要什么，AI负责写代码，人只需要看结果差不多就行。这个词随后传遍了整个技术社区，成了那一年AI编程讨论里出现最高频的术语。

一年后，他自己把它送进了博物馆。

替代它的新词叫 agentic engineering。区别不是表面上的叫法：过去你是跟AI对话让它帮你写代码，现在你是在编排一组Agent，每个Agent负责任务的一部分，你的主要工作变成了给它们下指令、检查输出、在跑偏时介入纠正。Karpathy说他现在99%的时间不直接碰代码。手写代码占比从80%掉到了20%——不是渐变，是翻转。

2025年12月 — coding agent"基本能用"的拐点

他给出了一个具体坐标：2025年12月。他说在那之前，coding agent"基本不能用"；在那之后，"基本能用"了。这个节点不是某个产品发布造成的，是底层模型能力越过了一条线——Agent开始能理解中等规模代码库的上下文，在多个文件之间做连贯修改，而不只是补全光标前那行代码。

这条线一旦越过，编程工具的竞争逻辑就不一样了。不再是谁的补全更准，而是谁对Agent的编排设计得更合理。

目前走在这条赛道最前面的有三个产品，但它们在回答三个完全不同的问题。

Cursor 的核心赌注，是大多数程序员不想改变工作习惯。

它把Agent塞进IDE里，但整个工作流基本没动。你还是打开VS Code（Cursor基于VS Code），还是看文件树、写代码、跑测试。Agent在后台读你的整个代码库，在你需要时介入——从单行补全到跨文件重构都能做，但做完了你能看到它改了什么，不认可随时可以拒绝。

这个判断是对的：Cursor在2026年初年化营收到了20亿美元，三个月翻了一倍。程序员愿意为这种"Agent在旁边但控制权在我这儿"的模式付钱。不过透明的代价是Agent的边界很窄——它不能自己跑测试、不能处理CI管道里的错误，方向盘始终在人手里。

Claude Code 解决的是另一个问题：有经验的开发者怎么把注意力从写代码转移出来。

它不在IDE里运行，是命令行工具。Agent直接在终端里工作，读文件、写文件、跑命令、看输出，然后根据结果决定下一步。一个任务下去，Agent可以自己找到问题、写修复、跑测试验证，甚至自己提交commit。Karpathy用它，反复提到的不是某个功能，而是"怎么给Agent拆任务"——任务描述模糊，Agent会在错误方向上跑很远才停下来。

Replit 则把"程序员"这个前提直接去掉了。

它面向的是有想法但不会写代码的人。你描述你要什么应用，Agent从零生成整个项目，前端后端数据库部署配置一起出来，不需要本地环境，不需要懂Git。应用能跑起来的时候，体验确实接近魔法。但一旦出了问题——性能瓶颈、安全漏洞、莫名其妙的bug——你面对的是一个完全没有参与构建的代码库。修复一个你不理解的系统，往往比从头重写更难。

三条路径的人机边界:

Cursor ── Agent在IDE内辅助，人类逐行审查

Claude Code ── Agent在终端自主执行，人类审查结果

Replit ── Agent全自动构建，人类只描述需求

换个角度看，这三条路其实在回答三个不同的问题。Cursor问的是：怎么让现有的程序员不用改变习惯就能更快？Claude Code问的是：怎么让有经验的开发者把注意力从写代码挪到更高层的判断上？Replit问的是：怎么让根本不会写代码的人也能把一个应用做出来？

这不是同一个问题的三种解法，是三家公司对"谁才是我们真正的用户"给出了不同的判断。

Karpathy自己站在Claude Code这边——他认为"人类编排Agent"比"Agent全自动"走得更远。

原因不复杂。软件工程不只是写代码。它是理解需求、做架构决策、权衡取舍、处理边界情况、在不确定性中做判断。这些事情目前的AI做不好。Agent可以替你写90%的代码，但剩下10%的判断——这个API要不要做向后兼容、这个数据要不要做冗余存储、这个异常该静默处理还是该报警——需要一个理解业务上下文的人来做。

编程的单元正在从'文件'变成'Agent'。但Agent的单元还是'判断'——而判断是人的。

— 对Karpathy观点的提炼

这里有一个更长远的问题。

如果编程的基本单元真的从文件变成了Agent，那"程序员"这个职业的定义就变了。过去，程序员是写代码的人。未来，程序员是编排Agent的人。这两种能力的重叠度并不高——一个写了十年C++的工程师，不一定比一个从未写过代码的产品经理更擅长给Agent下达清晰准确的指令。

Karpathy自己就是一个例子。他是全世界最顶尖的AI研究者之一，但他在分享Claude Code使用经验时反复强调的不是技术细节，而是"怎么写好一个prompt"、"怎么拆分一个任务让Agent能独立完成"、"怎么在Agent的输出中快速识别问题"。

这些是编排能力，不是编程能力。两者之间的鸿沟，可能会成为下一个十年软件行业最大的人才错配。

1908年，福特T型车量产之后，马车夫这个职业并没有消失。它分裂成了两个新职业：一部分人学会了开车，成为了出租车司机；另一部分人学会了修车，成为了汽车技师。但有一个能力变得彻底无用了——驾驭马匹。不是因为马变笨了，是因为车不需要马。

编程正在经历它的T型车时刻。写代码这个能力不会消失，但它在程序员技能栈中的权重正在快速下降。上升的是一种还没有被正式命名的能力：让Agent理解你的意图，并在你的监督下把意图变成可运行的软件。Karpathy管它叫agentic engineering。这个词能不能活下来不重要。重要的是它指向的那个变化已经发生了。
