## Lossless Claw

OpenClaw 跑长任务的时候，对话越来越长，上下文窗口装不下了怎么办？默认做法是砍掉旧消息。砍完之后，之前讨论过的方案、做过的决定，全没了

Lossless Claw 换了一种思路。不砍消息，**压缩存档**。所有对话存进 SQLite，旧消息压缩成摘要，摘要再压缩成更高层的摘要，形成一棵**有向无环图**。需要的时候随时展开还原

**3.3K Stars**，MIT 协议

---

## 默认的compaction有什么问题

OpenClaw 内置的上下文管理是滑动窗口。窗口满了，最早的消息直接丢弃

跑短任务没问题。但如果你让 Agent 做一个跨几十轮对话的项目，前面讨论的架构决策、排除过的方案、确认过的细节，窗口一滑就没了。Agent 会重复提问，甚至推翻之前的结论

不是它变笨了，是它**真的忘了**

---

## DAG压缩怎么工作

每条消息都存进 SQLite 数据库。当上下文占用超过窗口的 **75%**，触发压缩

压缩不是删除。它把一批旧消息交给 LLM 生成摘要，摘要保留关键信息和决策链路。摘要积累多了，再压缩成更高层的摘要节点。层层递进，形成一棵 **DAG（有向无环图）**

每次对话开始，拼接方式是：**高层摘要 + 中层摘要 + 最近32条原始消息**。既省 token，又不丢关键信息

---

## 三个工具随时回溯

装上之后 Agent 多了三个工具

**lcm_grep**：全文搜索历史对话。比如搜"数据库选型"，能找到50轮之前讨论过的内容

**lcm_describe**：查看某段对话的摘要，带来源归属。知道这个结论是哪轮对话产生的

**lcm_expand**：展开压缩过的摘要，还原成原始对话细节。压缩是可逆的

## 配置很简单

一行安装：`openclaw plugins install @martian-engineering/lossless-claw`

四个核心参数：**FRESH_TAIL_COUNT** 控制保留多少条最新消息不压缩，默认32。**CONTEXT_THRESHOLD** 控制压缩触发阈值，默认75%。**SUMMARY_MODEL** 可以指定一个便宜的模型专门做摘要，省主模型的钱

装上即生效，不需要改工作流
