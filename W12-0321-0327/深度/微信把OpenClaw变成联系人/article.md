腾讯做了一件看起来很小、但影响可能很大的事

据路透社 3 月 22 日报道，腾讯把 OpenClaw 接进了微信——不是作为一个小程序，也不是作为一个独立 App，而是作为一个**联系人**

用户在聊天界面里@ClawBot，就能直接调用 Agent 完成任务。微信的 10 亿+ 月活用户，不需要下载任何东西，不需要学习新界面，甚至不需要离开他们每天打开几十次的应用

这听起来像是一个产品更新。但如果我们把它放在整个 2026 年的背景下看，这可能标志着 Agent 竞争的逻辑正在发生根本性的转移

:::data 关键数据
- **10亿+** — 微信月活用户，OpenClaw 一夜之间触达的规模
- **79亿元** — 腾讯 2025Q4 资本开支，同比增长 86%，主要投向 AI 基础设施
- **20万+** — 接入 OpenClaw 的企业账号数量
:::

Agent 这个概念火了一年多。从最初的 ChatGPT，到后来的 Claude、Gemini，再到中国的文心、通义、豆包，大家的注意力一直集中在**模型能力**上——谁更聪明，谁能处理更长的上下文，谁的推理能力更强

但现在，腾讯用微信做了一个完全不同的示范：Agent 可以不那么聪明，但它必须**在你已经在的地方**

这种思路的转变，正在引发一场关于 Agent 入口的争夺战

---

阿里选择的战场是企业协作

同样是 3 月，路透社报道阿里推出了名为 Wukong 的 AI 平台。这个平台被定位为"工作大脑"，目标很明确：抢占企业用户的日常办公场景

阿里的逻辑很清晰——既然 Agent 最终要帮人完成工作，不如直接从工作场景切入。钉钉 7 亿用户、阿里云的企业客户群，都是现成的渠道

但 Wukong 的问题是，它依然要求用户**主动打开一个新的应用或界面**

百度的路径又不一样

沈抖在 3 月的采访中说了一句话："我们需要从关注'模型'转向关注'系统'。"百度把 Agent 看作一个操作系统级别的能力，而不是一个应用级别的功能

百度的"龙虾"系列 Agent——RockLobster、SpinyLobster、Nephropidae——分别针对创作者、旅行者和教师群体。它们被设计为跨平台运行，不依附于任何单一入口

> "一个模型解决一个问题的思路不再适用。你需要一个系统——一系列相互协作的模型和工具。"
> —— 沈抖，百度执行副总裁，2026年3月

三种策略，三个方向：

- **腾讯**：利用现有超级入口（微信），把 Agent 变成基础设施
- **阿里**：从企业协作场景切入，试图重新定义工作流程
- **百度**：构建跨平台的 Agent 系统，不依赖单一入口

看起来三方各有优势。但如果我们停下来仔细想，会发现这里有一个被忽略的关键问题

---

入口大，不等于执行顺

微信有 10 亿用户，这是事实。但微信用户**习惯**的交互方式——聊天、发朋友圈、刷视频号——和 Agent 的交互逻辑并不天然契合

当用户@ClawBot 让它订机票时，谁来确认具体的航班时间？如果 Agent 理解错了目的地，谁来纠正？如果出了问题，用户是找微信客服、找腾讯、还是找 OpenClaw？

这些问题看起来琐碎，但它们决定了 Agent 能不能真正被用起来，而不是成为一次性的尝鲜

阿里和百度其实也面临类似的困境。钉钉用户习惯了在群里@同事，但@一个 AI 助手来协调项目，和@同事是完全不同的心理契约。百度的跨平台 Agent 理论上更灵活，但这也意味着它没有明确的场景锚点，用户不知道什么时候该用它

:::struct 三方策略对比
腾讯微信：利用超级入口，Agent 作为基础设施层
阿里钉钉：从企业协作切入，试图重构工作流
百度系统：跨平台 Agent 网络，弱化单一入口依赖
:::

更深一层的问题是**权限与责任**

当 Agent 被集成进微信，它实际上获得了访问用户聊天记录、联系人、支付信息的潜在能力。这些权限的边界在哪里？用户是否有足够的知情权？

腾讯在官方声明中强调，OpenClaw 在微信内的权限是"受控的"，并且用户可以手动关闭。但这种解释回避了一个核心问题：**默认开通的便利性，和手动关闭的知情成本，是不对称的**

大多数用户不会去看权限设置。他们会假设，既然微信官方集成了这个功能，那应该是安全的。一旦 Agent 出错——无论是订错了票、泄露了信息、还是做出了不当推荐——责任的归属会变得非常复杂

这不是技术问题，这是**治理结构**的问题

---

所以，这场竞争的本质是什么？

表面上看，是腾讯、阿里、百度在争夺 Agent 的入口权。但往深处看，这其实是关于**下一代人机交互界面**的定义权

移动互联网时代，手机操作系统是入口。iOS 和 Android 决定了用户如何接触应用、如何消费内容、如何完成交易

但在 Agent 时代，操作系统可能不再是唯一的入口。Agent 本身可以成为入口——它可以直接调用服务、完成任务，而不需要用户打开具体的应用

微信试图成为这个新时代的"操作系统"。它不想只是一个通讯工具，它想成为用户**完成一切事情的默认环境**

阿里的焦虑和百度的分散式策略，都是对腾讯这个野心的回应

:::data 资本动向
- 深圳龙岗区出台政策，单个企业最高可获得 1000 万元 OpenClaw 研发补贴
- 无锡发布"算力券"政策，支持企业接入 OpenClaw 生态
- 合肥、杭州等地陆续跟进，Agent 产业成为地方招商引资新热点
:::

地方政府已经嗅到了风向。深圳、无锡、合肥、杭州等地陆续出台支持 OpenClaw 生态的政策，从算力补贴到应用奖励，试图在这场新的平台战争中占据一席之地

这让人想起智能手机早期的格局。iPhone 刚出来的时候，诺基亚、黑莓、摩托罗拉都在做手机，但它们竞争的是"更好的手机"，而不是"下一个计算平台"

今天，Agent 的竞争也可能面临同样的陷阱——大家在比拼功能、比拼接入的平台数量、比拼模型能力，但真正决定胜负的，可能是**谁能重新定义用户的行为习惯**

---

微信把 OpenClaw 变成联系人，这个动作的真正意义，不在于技术有多先进，而在于它改变了一个基本假设：

Agent 不再是一个你需要去找的工具，而是一个**会主动出现在你身边的助手**

这个转变的影响是深远的。它意味着 Agent 的竞争单位，正在从"模型能力"转向"渠道能力"。谁能把 Agent 放进用户最自然的使用场景，谁就能赢得这一轮

但这同时也带来一个风险：当 Agent 变得无处不在，用户可能会逐渐失去对"谁在为我服务"的感知。便利性和控制权的边界，会变得越来越模糊

智能手机让我们习惯了"永远在线"，Agent 可能让我们习惯"永远被代理"

这两种状态的区别，不在于技术，而在于我们是否还清楚自己和工具之间的界限

---

> 真正需要警惕的，不是 Agent 会不会做事，而是它开始住进你每天已经在用的入口，而你甚至不会记得，是什么时候邀请它进来的
