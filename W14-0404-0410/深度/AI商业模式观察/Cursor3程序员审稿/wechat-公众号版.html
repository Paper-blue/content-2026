SUBTITLE

IDE的主界面不再是代码编辑器了。打开Cursor 3，你看到的是一个agent调度台。

4月2号，Cursor发了3.0。

我更新完打开的那一瞬间愣了一下——主界面变了。以前打开一个代码编辑器，正中间是你写代码的地方，左边是文件目录，下面是终端，跟过去二十年的编程工具长得差不多。但Cursor 3打开之后，正中间变成了一排agent的对话窗口，左边是一个正在跑的agent列表，有的在本地机器上跑，有的在云端跑，每个都有自己的状态和进度条。

你就说离不离谱，就像你以前打开的是一张书桌，上面摊着稿纸和笔，现在打开变成了一个调度室的大屏幕，上面有五六个施工队的实时画面。

你不写了，你就坐在那儿看着它们干活。

打开Cursor 3的第一眼，编辑器不再是主角了

先给不写代码的朋友解释一下IDE是什么。IDE就是程序员的灶台——切菜、翻炒、调味、装盘，所有动作都在这一个台面上完成。我每天对着IDE的时间比对着任何人都长，基本就是八到十个小时，手指头不停地敲。厨师跟灶台是什么关系，写代码的人跟IDE就是什么关系。

Cursor是这两年最火的AI代码编辑器，2023年从微软的VS Code分叉出来，做成了一个"AI帮你写代码"的工具。到2025年底已经有几百万开发者在用。但说白了，3.0这次更新不是加了个新功能那么简单——它把灶台本身换掉了。

Cursor官方博客写了一句话，大意是：软件开发正在进入"第三个时代"，大量的agent自主协作完成开发工作。我读完愣了两秒，翻译成人话就是——你是包工头，agent是施工队。

Cursor 3 核心变化:

主界面 ── 从代码编辑器变成 agent 管理面板

并行能力 ── 本地 + 云端多个 agent 同时跑

会话迁移 ── 桌面、手机、Web、Slack、GitHub 之间无缝切换

旧 IDE ── 还在，但降级成了辅助窗口

那这个所谓的"第三个时代"，前两个是什么？

我回头捋了一下，其实三个阶段切得很干净。

2022年，GitHub发了Copilot，这是第一个大规模商用的AI编程工具。它干的事很简单——你写了半行代码，它帮你把后半行补完。就像厨师切了两刀葱，旁边有个助手帮你把剩下的葱切完了。挺好用的，但你还是那个掌勺的人，所有动作的起点都是你。

2024年，ChatGPT和Claude的对话功能越来越强，你可以直接跟AI说"帮我写一个登录功能"，它给你吐一整块代码出来。等于厨师不用自己切葱了，直接跟助手说"帮我把这道菜的备料全做了"。但你还得亲自检查备料对不对，然后亲手炒。

2026年，Cursor 3。你不切菜了，也不炒菜了。你同时指挥五个agent在五个锅上同时干活，有的在做前端，有的在写后端，有的在跑测试。你干的事变成了：看看每道菜出品质量过不过关，提交代码前做终审。

从补全到对话到调度。三年走完了。

DATA — AI编程工具演化

2022 — Copilot：AI补全代码（写了半行帮你补完）

2024 — Claude/ChatGPT Chat：AI写完整功能（给描述吐代码）

2026 — Cursor 3：AI自己跑，人只审核（并行agent管理）

Cursor 3发布三十分钟之后，Hacker News上最高赞的评论写的是："我希望他们能保留让开发者主导、agent辅助的旧哲学。"有人直接说："我还是想写代码，不想靠vibe来处理工单。"

说实话我看到这条的时候挺有共鸣的。

Cursor的工程师几分钟之内就回复了，说IDE还在，你随时可以切回去写代码，新的agent窗口是独立的，不想用可以不打开。

但这个回复本身说明了一个事——现在需要向用户保证"你仍然可以亲手写代码"。你想啊，三年前这句话是不需要说的，因为打开工具你就是在写代码。

Hacker News上那条评论戳中的其实不是功能问题，是身份问题。写代码这件事对程序员来说不只是工作内容，它是职业身份的核心。就好比你跟一个厨师说"以后你不用炒菜了，你只要验菜就行"——他可能会说谢谢，但心里那个"我是厨师"的认同会有点晃。

— 01 —

好，说到这儿你可能觉得：行吧，agent替你写代码，你验收就行，好像也不错，能省不少力气。

但有个数据咱不能假装看不见。

Veracode的2025年报告测了100多个大语言模型生成的代码，结果是45%含有安全漏洞。Java最惨，安全测试失败率到了72%。86%的代码样本扛不住跨站脚本攻击，88%扛不住日志注入。

到了2026年，AppSec Santa又做了一轮，测了534个代码样本，结论是每四段AI生成的代码里就有一段有安全漏洞。而且2026年3月有35个CVE漏洞编号被确认是AI生成的代码直接导致的，一月份这个数字才6个。

AI经常能产出能跑的代码，但极少产出能安全部署的代码。

— 瓦伦·巴德瓦尔（Varun Badhwar），Endor Labs CEO

所以"审稿"这个活，听着好像比"写稿"轻松，但我自己的体感是——审一段你没写过的代码，比自己从头写更难。你得理解它想干什么，得看出它没做什么，还得判断它偷偷埋了什么坑。初级程序员审不了这个活，因为你得先知道什么是对的，才能看出什么是错的。

说白了，从"写代码的人"变成"审代码的人"，不是降级，但对能力的要求结构完全变了。以前我觉得写代码靠的是手速快、语法熟、框架会得多。现在回头看，真正值钱的是架构思维清晰、安全意识过硬、能在别人写的东西里看出问题。

这跟出版行业的变化有点像。自媒体时代之前，编辑需要自己能写。现在内容来源太多了，编辑最核心的能力变成了判断——什么该发，什么不该发，什么得改，什么有风险。

— 02 —

那问题来了，这个变化只影响程序员吗？

哈佛商业评论2026年2月正式定义了一个新岗位叫"AI Agent Manager"——负责给agent分配任务、审核agent的产出、处理agent搞不定的异常、根据结果优化agent的工作流程。

我看完这个定义的反应是——这不就是Cursor 3里面程序员正在干的事吗。

但有意思的是，哈佛那个定义说的不只是程序员。项目经理、运营主管、质量分析师——任何原来就在管流程、管人的人，都可能滑进这个角色。而且他们还特别强调了一点：做这个岗位，行业经验比AI经验重要。

这个新岗位就像2005年的"社交媒体经理"。那时候没人知道这是个工种，到2015年它已经是标配了。"AI Agent Manager"可能也在走同一条路，只不过时间压缩了——不需要十年，可能三到五年。

Cursor 3其实是这个趋势里的一个具体产品落地。它不是唯一一个在往这个方向走的——Claude Code现在已经超过了GitHub Copilot成为使用率最高的AI编程工具，41%对38%。Copilot也加了agent模式，能自己提交代码改动。整个行业都在从"AI帮你写"往"AI自己写、你来审"这个方向挤。

但你注意，Cursor 3做了一个别人没做的事：它把IDE的主界面让出来了。别的工具是在编辑器旁边加了个agent面板，Cursor是反过来的——agent面板是主界面，编辑器变成了可以随时切过去的辅助窗口。

这个设计选择我觉得很说明问题。它不是在说"agent可以帮你"，它是在说"你的主要工作已经不是写代码了"。

— 03 —

程序员没有消失，也不会消失。但"程序员"这三个字的意思在变。三年前它的意思是"一个打字很快、逻辑很强、能把需求翻译成代码的人"。现在它正在变成"一个能管住一群agent、看得出代码有没有坑、在架构层面做判断的人"。

这不是降级。审稿比写稿难，因为你得在别人的逻辑里找到你自己的判断。但这确实是一次身份重构——就像从记者变成主编，活没少干，但你跟键盘的关系变了。

说白了，程序员还在，但"程序员"这三个字的意思已经不一样了。
