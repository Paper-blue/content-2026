## 痛点

你在用 Claude Code 写代码，写到一半想切换到 GPT-4o 试试效果。

换不了，或者换了，上下文全没了。

你想把 AI 助手嵌进自己的工具或者 Slack，发现要对接好几套不同的 API 格式，写了两天还在调试。

现有方案，要么锁死厂商，要么要你重复造轮子。没有一个真正厂商无关、可以自由拼装的。

---

## 核心就 4 个工具

pi-mono 的理论很简单：一个编码 Agent，只需要能读文件、写文件、编辑文件、跑命令，就够了。

**read、write、edit、bash**，四个工具，没有计划模式，没有 MCP，没有权限弹窗。

系统 prompt 不到 **1000 token**，是 Claude Code 的十分之一。Terminal-Bench 2.0 测试里，pi + Claude Opus 4.5 的结果和功能更复杂的工具持平。

---

## 统一 LLM API 层

想把 AI 能力嵌进自己的应用？用 `@mariozechner/pi-ai` 这个包。

它屏蔽了 OpenAI、Anthropic、Google 的 API 差异，统一格式，支持**跨模型上下文迁移**——Claude 里开的对话，换 GPT 继续，格式自动转换。

之前：换个模型要重新对接 API，上下文手动转。
现在：一套接口，随时切，上下文跟着走。

## UI 套件按需取用

`pi-tui` 做终端界面，`pi-web-ui` 做浏览器界面，`pi-mom` 接 Slack。

各包独立，不用整包引入。想要什么功能装什么，不绑定。

## 适合谁

适合你，如果：你在用 TypeScript 写项目，想搭一个自己掌控的 AI 工作流，或者需要把编码 Agent 嵌进团队工具里。

不适合，如果：你只想找一个开箱即用的 GUI 工具，或者项目不在 TypeScript 生态。

想掌控 AI 工具链、不想被厂商绑定的开发者，值得认真看一下。

## 如何获取

GitHub: badlogic/pi-mono（**14.3K ⭐️**）

编码 Agent 单独安装：

npm install -g @mariozechner/pi-coding-agent

在任何项目目录运行 `pi` 即可启动。
