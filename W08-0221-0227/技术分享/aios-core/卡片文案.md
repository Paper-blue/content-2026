**aios-core**：AI 辅助开发时，上下文丢失的问题。

**1.5K ⭐️**，本周新增 1,159 stars，v4.0 版本。

---

## 痛点

每次打开 Claude Code 或者 Cursor，第一件事是什么？

"这个项目是做什么的、用了哪些技术、现在在做哪个模块……"

重新解释一遍。AI 给出的建议，仍然是对着陌生代码库瞎猜的。

现有方案，要么上下文全靠你手动粘，要么 Agent 之间各说各话，没有一个真正让 AI 持续"认识"你项目的。

---

## 两步走：先规划，再动手

aios-core 的做法是把开发拆成两个阶段。

**第一步先规划**：@pm 和 @architect 两个 Agent 协作，生成完整的 PRD 和架构文档。这份文档不是给你看的，是留给后续每个 Agent 读的。

**第二步才动手**：@sm 把规划拆成一个个 story 文件，@dev 拿着 story 去实现，@qa 做测试和代码审查。每个 story 里带着足够的上下文——Agent 不用猜你在做什么。

---

## 11 个专属 Agent

框架内置 **11 个专属 Agent**，分规划、开发、质量三类。

支持 Claude Code、Codex CLI、Gemini CLI、Cursor 四种 IDE 集成。CLI 优先设计，核心功能不依赖图形界面。

之前：每次开新对话都要重新解释项目背景。
现在：story 文件承载上下文，Agent 接力，不断档。

---

## 门槛说明

需要 Node.js 18+、npm 9+，命令行基础。

有 `npx aios-core doctor` 诊断命令，自动检查和修复常见配置问题。第一次配置大概 15-20 分钟。

---

## 适合谁

适合你，如果：你在用 AI 辅助开发、项目超过单文件、经常遇到 AI 答非所问。

不适合，如果：你只是偶尔问 AI 几个代码问题，直接用 ChatGPT 够了。

有 Claude Code 使用习惯的开发者，值得花半小时试一下。

## 如何获取

GitHub：SynkraAI/aios-core（**1.5K ⭐️**）
